# История изменений

## 1.2.31

- У идущего ручного бекапа есть кнопка «Прервать». Конфигуратор, SQL и скачивание останавливаются. Если машина уже была выключена, её включают обратно.

## 1.2.30

- Файлы виртуальной машины пишутся в хранилище по мере скачивания, а не одним архивом в конце. В журнале видно, сколько мегабайт уже получено.

## 1.2.29

- Если подключение указывает на vCenter, файлы выключенной машины скачиваются через API vCenter, а не через vim-cmd по SSH.

## 1.2.28

- Файлы виртуальной машины снимаются через оболочку гипервизора. Если команды tar там нет, архив собирается на этой машине.

## 1.2.27

- Выключение виртуальной машины больше не срывается на таймауте ответа vSphere: состояние опрашивается до 10 минут, затем питание выключается принудительно.
- Если бекап машины не получился, задача остаётся ошибкой и машину пытаются включить обратно.

## 1.2.26

- Кнопки снова используют стиль ghost.
- Бекап и подключение к серверу правятся в окне.
- Готовые копии перечислены и их можно восстановить.
- Включение виртуальной машины после бекапа пробует оба адреса vSphere и SOAP, если первый отвечает 404.

## 1.2.25

- BACKUP DATABASE больше не запускается внутри транзакции pymssql.
- Если кластер 1С представляется именем, которого нет в DNS, оно записывается в hosts на адрес сервера и выгрузка повторяется.

## 1.2.24

- Журнал конфигуратора 1С попадает в лог бекапа, а не только фраза «завершился с ошибкой».
- У бекапа базы можно указать пользователя информационной базы. Логина администратора кластера для выгрузки недостаточно.

## 1.2.23

- У уже сохранённого сервера MSSQL есть поля «Логин Windows» и «Пароль Windows» и кнопка «Сохранить доступ к диску».

## 1.2.22

- Бекап удалённого MSSQL больше не требует диск CIFS: файл .bak пишется на диск C: SQL Server и забирается на эту машину, затем копируется в выбранное хранилище.
- Конфигуратор 1С на сервере без экрана запускается через xvfb.

## 1.2.21

- Ручной и автоматический бекап показывают процент, текущий шаг и подробный журнал по ходу работы.
- Пункт меню «Диски» переименован в «Хранилища» и стоит сразу под «Машины».
- Журнал обновления системы на странице «Обслуживание» обновляется каждую секунду.

## 1.2.20

- Перед запуском конфигуратора ставится набор библиотек клиента 1С, включая libsm6 (libSM.so.6). Неизвестная библиотека ищется по имени пакета и ставится повторным запуском.

## 1.2.19

- Обновление с панели больше не останавливается из-за пустого HOME и локальных правок в исходниках. Каталог на сервере заменяется точной копией ветки main.

## 1.2.18

- Подключение к SQL Server больше не требует протокол TDS 7.4, которого нет в pymssql из Ubuntu. Используется версия, которую понимает установленный драйвер.

## 1.2.17

- Перед бекапом конфигурации ставится libcups2, без которой конфигуратор 1С не запускается. Если не хватает другой библиотеки, она ставится и запуск повторяется.

## 1.2.16

- Вход в vCenter 7 (VCSA) больше не шлёт пустое JSON-тело, из-за которого сервер отвечал 401 и не видел пароль.
- Для типа vSphere сначала пробуется логин с @vsphere.local.

## 1.2.15

- Вход в vSphere 7 и ESXi шлёт пароль в обычном SOAP-поле, без CDATA, и пробует службы ha-sessionmgr и SessionManager.
- У гипервизора можно заново ввести пароль перед обновлением списка. В ошибке видна длина сохранённого пароля.

## 1.2.14

- Кнопка «Запустить» стартует бекап сразу и показывает журнал под ним. Если папки назначения нет, она создаётся.
- Пакет и обновление сами ставят python3-pymssql, а если его нет в репозитории — mssql-tools18.
- Вход в vSphere 7 не теряет пароль на переадресации и пробует имя с @vsphere.local.

## 1.2.13

- Список баз MSSQL читается сразу при подключении. Ответ sqlcmd в UTF-16 больше не прячет имена, ошибка соединения пишется на карточке сервера.

## 1.2.12

- Страница MSSQL: сервер запоминается, базы выбираются из списка, у каждой свои бекапы. Файл .bak пишется на диск CIFS или на локальный SQL.

## 1.2.11

- Кнопка обновления появляется только если на GitHub есть версия новее установленной, и на ней написан номер этой версии.

## 1.2.10

- У пользователя в разделе «Доступ» можно сменить отображаемое имя и логин.
- Чужую учётную запись можно заблокировать и снова разблокировать. Свою заблокировать нельзя.

## 1.2.9

- У каждого бекапа своё расписание: дни, время и ручной запуск. Планировщик сам запускает включённые задания.
- У бекапа задаётся папка на диске и, если выбрано облако, отдельная папка для копии.

## 1.2.8

- Вход в vSphere 7 и ESXi 7 не теряет пароль на переадресации.
- SOAP для этих версий использует протокол 7.0, а не 6.7.

## 1.2.7

- У подключённого диска и облака есть просмотр содержимого: каталоги открываются, виден размер и дата.

## 1.2.6

- ESXi 6.7, где REST отвечает 400, читается через SOAP: список машин, мягкое выключение и включение.
- Релиз и история каждый раз заново читаются с GitHub и не сохраняются в браузере.

## 1.2.5

- Список баз передаёт администратора кластера после команды `rac`, а не до неё.
- Вход в ESXi 6.7 идёт без тела запроса и с заголовком `vmware-use-header-authn`.

## 1.2.4

- Описание релиза читается из `README.md` на GitHub, а не из заметки к тегу.
- Отдельная страница истории читает этот файл с GitHub.
- Название продукта в интерфейсе: «Консоль платформы».
- Ссылки на GitHub открываются в новой вкладке.

## 1.2.3

- Обновление из панели запускается отдельно от службы и не обрывается при перезапуске.
- Сеть показывает каждый интерфейс. Для него задаются DHCP или адрес, шлюз и DNS.
- Правила фаервола выводятся списком, их можно менять и удалять.
- Часовой пояс выбирается из списка системы.

## 1.2.2

- Вход в ESXi больше не падает до проверки логина и пароля.

## 1.2.1

- Верный пароль больше не возвращает на форму входа.

## 1.2.0

- Ставятся сервер, толстый и тонкий клиент.
- Базы и виртуальные машины выбираются из списка, а не вводятся вручную.
- У одной базы или машины может быть несколько бекапов. Старые копии удаляются по сроку хранения.
- Страницы системы, обслуживания и сведений о релизе.

## 1.1.0

- Диски WebDAV, CIFS, NFS и FTP. Дополнительные копии в Google, Яндекс и Mail.ru.
- Бекап виртуальных машин ESXi и vSphere: мягкое выключение, копия, включение.
- Расписание для каждого бекапа.
